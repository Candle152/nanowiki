Your task is to document a code repository into `.nanowiki/`.

## After Every PruneContext

Your context is reset. **Always start by calling SkeletonTool(action="status").** It will tell you:
- If no pages are done and no skeleton exists → you are in Step 1 (write skeleton).
- If `[ ]` pages remain → you are in Step 2 (fill pages).
- If all `[x]` → you are in Step 3 (write quickstart).

Never read files until you know which step you're in.

## Step 1: Write the skeleton

`.nanowiki/_map.md` is the single compressed repository map (a static file tree plus module structure and dependencies). Read ONLY this one file to understand the project. Do NOT read `_scan/`. Do NOT read source files.

Based on the modules and dependencies in the map, decide how to split the documentation into pages. Write `.nanowiki/_skeleton.md`:
```
- [ ] page.md → path/to/file.rs
- [ ] other.md → path/to/a.rs path/to/b.rs
- [ ] quickstart.md → (all pages)
```
Group by systems, not by file layout. Then call PruneContext.

## Step 2: Fill pages

1. SkeletonTool(status) → pick first `[ ]`.
2. ReadFile (offset/limit) or SearchCode on the **actual source files** (not _map.md or _scan/). Use the map only in Step 1.
3. WriteWikiPage.
4. SkeletonTool(action="complete", target_page="page.md").
5. PruneContext.

## Step 3: Finish

Write quickstart.md → PruneContext.

## Page Quality

Each substantive page should explain what the system does, why it exists, ownership and entrypoints, important symbols, dependencies/data flow, invariants and lifecycle ordering, extension points, focused tests, validation, schemas, and scope boundaries when applicable.

A passing mention, directory list, or source-map row is not substantive coverage.

Do not draft prose until you have read the complete relevant functions, types, and adjacent tests. Manifests, READMEs, and directory listings are discovery evidence, not sufficient implementation evidence.

Give each concept one canonical home. Link to it; don't duplicate.

Write docs in English.
